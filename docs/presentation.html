Огляд

Що таке Sekta

Набір незалежних застосунків обліку для військового підрозділу на спільному стеку. Кожен самодостатній; усі закриті єдиним гейтом і мають наскрізний аудит «хто / коли / звідки».

PostgreSQL

База даних кожного застосунку + централізований журнал аудиту.

Node-RED

Бекенд-логіка у function-нодах: запити, ідемпотентність, аудит.

Dashboard 2.0

Фронтенд: .vue-віджети, єдина дизайн-система.

Особовий склад (HR)

Повний облік військовослужбовця: від картки до статистики, кадрового руху й вітрини командира.

Базакартка, родина, освіта, нагороди, поранення Кадризвання, УБД, переміщення, довідки Кандидатирекрути, етапи, зріз Соцсупровідвідпочинок, діти, поранені Нагородиродичі, ДР, автотранспорт TVстан кандидатів, рух о/с, ДН
  • Наступні звання — розрахунок на читанні + дні на СБЗ зі Стройовки.
  • Заявки DOCX — на звання, на довідки (лист із гейтом доступу).
  • Контроль повноти даних — критичні поля одним поглядом.
  • ВПО / ТОТ — фільтри та позначки родини на окупованій території.

Гейт та адміністрування

Єдина точка входу й керування: логін + 2FA перед усіма дашбордами, керування користувачами, оновлення та безпека.

Вхід + 2FAлогін перед Node-RED Користувачістворення, блокування, backup-коди Оновленнязашифровані архіви, міграції Логи · nginx · 2FAадмін-панель Майстер налаштуванняпокроковий провіжинг
  • Ідентифікація «довозиться» у кожен запит — позивач у заголовку від гейта.
  • AU-9 append-only — журнал аудиту неможливо стерти навіть адмінам.
  • Ротація секретів, мережева ізоляція БД, governed retention 3 роки.
Безпека · комплаєнс

Відповідність нормам безпеки

Система sekta-update реалізує базові профілі безпеки НАД № 409 (відкрита/конфіденційна) та № 419 (службова інформація; включає 409). Mapping — НД ТЗІ 3.6-006-24 / NIST 800-53. Технічну частину базових профілів фактично завершено.

Багатофакторність

IA-2 — TOTP + FIDO, стійкість до відтворення. Блокування спроб (AC-7).

Аудит append-only

AU-9 — журнал захищено від підробки: non-superuser роль, SECURITY DEFINER, REVOKE mutate.

Журнал змін «хто/коли/звідки»

AU-3/6/7 — автор + IP (changed_ip) у кожному записі; UI перегляду/фільтр/diff/CSV.

Паролі та крипто

IA-5 — ≥12 символів, scrypt-зберігання; TLS 1.2/1.3 + AEAD (SC-8/13); дампи at-rest AES-256-GCM.

Периметр і сесії

SC-7 firewall «заборонити все»; idle-таймаут 15 хв (SC-10/AC-11), припинення сеансу (AC-12).

Кероване зберігання

AU-11 — ротація/архівація логів і записів аудиту БД (строк 3 роки, з архівацією).
