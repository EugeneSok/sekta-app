Огляд

Що таке Sekta

Набір незалежних застосунків обліку для військового підрозділу на спільному стеку. Кожен самодостатній; усі закриті єдиним гейтом і мають наскрізний аудит «хто / коли / звідки».

PostgreSQL

База даних кожного застосунку + централізований журнал аудиту.

Node-RED

Бекенд-логіка у function-нодах: запити, ідемпотентність, аудит.

Dashboard 2.0

Фронтенд: .vue-віджети, єдина дизайн-система.

hr

Особовий склад (HR)

Повний облік військовослужбовця: від картки до статистики, кадрового руху й вітрини командира.

Базакартка, родина, освіта, нагороди, поранення Кадризвання, УБД, переміщення, довідки Кандидатирекрути, етапи, зріз Соцсупровідвідпочинок, діти, поранені Нагородиродичі, ДР, автотранспорт Вітрина TVстан кандидатів, рух о/с, ДН
  • Наступні звання — розрахунок на читанні + дні на СБЗ зі Стройовки.
  • Заявки DOCX — на звання, на довідки (лист із гейтом доступу).
  • Контроль повноти даних — критичні поля одним поглядом.
  • ВПО / ТОТ — фільтри та позначки родини на окупованій території.

sekta-update

Гейт та адміністрування

Єдина точка входу й керування: логін + 2FA перед усіма дашбордами, керування користувачами, оновлення та безпека.

Вхід + 2FAлогін перед Node-RED Користувачістворення, блокування, backup-коди Оновленнязашифровані архіви, міграції Логи · nginx · 2FAадмін-панель Майстер налаштуванняпокроковий провіжинг
  • Ідентифікація «довозиться» у кожен запит — позивач у заголовку від гейта.
  • AU-9 append-only — журнал аудиту неможливо стерти навіть адмінам.
  • Ротація секретів, мережева ізоляція БД, governed retention 3 роки.
Наскрізне

Що спільне для всіх

🔎 Аудит «хто/коли/звідки»

Кожна зміна — з позивним, IP і часом. Журнал append-only (AU-9), retention 3 роки.

🛡️ Контроль доступу

Права на завантаження/дії по сторінках, адміни, майстер-ключ. Керування — у «Активності».

🔔 Сповіщення та Помилки

Дзвіночок останніх змін + окремий контроль помилок обліку в кожному застосунку.

🎨 Єдина дизайн-система

Спільна палітра, компоненти, a11y, мобільна адаптація — design.md.

📄 Документи

DOCX/PDF/XLSX генерація з реальних таблиць, гейт доступу до завантажень.

🧩 Захист від дублів

Ідемпотентні записи (client_token + ON CONFLICT) на рівні БД.

Технологія

Як це працює

Кожна дія проходить єдиний ланцюг — від віджета до бази й назад, із аудитом у тій самій транзакції.

Користувач→ Гейт (2FA)→ Dashboard 2.0 (.vue)→ Node-RED (function)→ PostgreSQL + аудит→ SELECT назад у UI

Ідемпотентність

Один клік = один запис, незалежно від повторів.

Без оптимізму

Таблиця оновлюється лише свіжим SELECT — фронт не «вигадує» дані.

Ізоляція

Кожен віджет — власний CSS-простір; спільні лише shared-компоненти.

Порядок взаємодії

Єдиний цикл роботи

Регламент зв'язує служби в замкнутий контур — від використання до навчання й зворотного зв'язку.

1 Використання→ 2 Фіксація багів→ 3 Пропозиції→ 4 Реалізація→ 5 Тестування→ 6 Викат→ 7 Навчання↺
  • Оператори + розробники — фіксація багів, тріаж.
  • Керівники, начальники служб — пропозиції та розпорядження.
  • QA + юрист — тестування, реліз, фіксація в наказі НЦ.
  • Навчання — відео-інструкції операторам.
